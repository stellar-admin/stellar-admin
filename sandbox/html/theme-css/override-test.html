Theme-as-CSS override semantics

1. Base + variant + size from CSS only

Expect: primary, red, and bordered small buttons — identical shape to today's server-resolved output.

2. Author override via app-bundle utility

Expect: solid blue button. The app bundle's .bg-blue-500 (utilities layer) must out-rank the theme's .sa-button-variant-default background (components layer) — including while hovered: the variant's hover:bg-primary/90 also lives in the components layer, so the author's static background wins even on hover. (Today tailwind-merge keeps the hover class; this is the one intentional semantics change.)

3. Theme hover state intact without override

Expect: transparent at rest, accent background on hover (from the components layer's &:hover).

4. Token with no rule
