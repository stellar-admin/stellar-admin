Card layout

The card in the index page's Cards layout. A developer fills a fixed set of parts from the resource's properties (image, title, description, badge, stats, fields) and picks the image shape, the image placement, the orientation, the field layout and the actions placement. Selection, click-through and the grid come from the index page and have no options.

The cards sit inside the list card with the scopes, search and pager, as the table does. Below, each option is shown once on the same record, so only that option changes.

4. Field layout

The same four fields two ways. Rows reads best for any field; grid trades some of that for height.

5. Stats

A separate part above the fields, for 2–4 short values (counts, prices, ratings). Either part can be left out, and the fields keep their own layout.

6. Actions placement

One set of row actions (here Edit, Publish, Delete) rendered in either place. In the menu they all go in the ⋯ menu in the header. In the footer, the first two are buttons and the rest go in a ⋯ menu at the end of the footer, so the header has no menu.

7. Fixed behaviour

With bulk actions on the index, every card gets a checkbox. A keyboard user tabbing to a card gets the focus ring around the whole card, since the title link covers it; the checkbox, menu and footer buttons are separate tab stops with their own rings. A value too long for its space ends in "…" and shows in full on hover (the browser's own tooltip, mocked here so the screenshot shows it).

8. Narrow screens

When the grid is under 30rem wide, a horizontal card stacks like a vertical one, with the image on top. This is a 360px phone with the cards configured horizontal; section 2 shows the same configuration wide.

9. Title over the image: which shape by default

The same overlay card twice. Built now: the title sits over the image in the image's shape, which defaults to widescreen (16:9). The prototype's earlier default: an overlay card without a shape set is 4:3, taller, so the shade and the title cover less of the photo. A shape set explicitly wins either way.
