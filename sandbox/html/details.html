Details (sa-details / sa-display-field)

Read-only label/value display, Filament's infolists, built on the sa-field infrastructure: sa-details is a column grid around a <dl>; each sa-display-field is an sa-field with a dt label and a dd value, and keeps orientation. The live candidate (top) is the recommended default: muted label, medium-weight value. Each section below compares one open question; pick a letter per section.

Model used by the snippets

Every snippet is proposed, uncompiled Tag Helper markup. Labels come from [Display] unless label overrides them; formatting comes from metadata ([DataType], [DisplayFormat]) unless format overrides it; child content replaces value rendering entirely. Templates resolve by name only (template or [UIHint]) from MVC's DisplayTemplates/; the tag helper never looks one up by type, so MVC's built-in type templates never apply. Where options differ only in default styling (A, D), they share one snippet.

Candidate: a booking's view page

Split form sections holding details, the default label style, two columns, and an audit section in divided horizontal rows.

A · Label and value typography

A1 is the candidate (Stripe/Linear: the value carries the weight). A2 matches an input's label so details and forms look alike. A3 is the docs' current row-detail sample.

B · Arrangement

All four are attributes (orientation, variant); defaults are stacked and not divided. B1 stacked in columns. B2 horizontal (label column 1fr, value 2fr). B3 horizontal with rules between rows (Filament's inline labels / Tailwind UI description lists). B4 responsive: stacked when narrow, horizontal when wide. Resize the window or check mobile.

C · Mixed with inputs on an edit page

Display fields inside a form section beside inputs (a read-only booking code next to an editable name), plus an audit section. Chosen: C2. Only display fields placed directly among inputs (outside sa-details) take an input's label style and a control's height; sa-details inside a form looks as it does anywhere else. Rejected: C1 plain text (misaligned rows), C3 tinted well (reads as a disabled input).

D · Empty values

The placeholder for null/empty. Zero and false stay real values. Placeholder text is per field (placeholder="Never"); this picks the default.

E · Value kinds

Built-in rendering happens in C# inside the tag helper (as the data grid does): booleans as an icon, enums as plain text, [EmailAddress]/[Url] as links. Everything else here is template (a named partial in DisplayTemplates/, or [UIHint]) or child content.

F · In a row-detail panel

Chosen: F2. The same sa-details markup gets caption labels inside a row detail, through a contextual rule; elsewhere it uses A1.

G · View-page sections

G1 is the live candidate (split sections). G2 card sections. G3 stacked sections, each a divided horizontal list.
