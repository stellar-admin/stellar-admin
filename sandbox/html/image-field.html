Image field

One property storing a reference to an image (a full URL, a file name or a storage key); the app's resolver turns it into the URL the browser loads. One section per template: grid display, grid editor, display, editor. Each starts with the recommended candidate, then the numbered questions with lettered options; click a letter to choose. The sample photos are deliberately mixed: square, 3:2 landscape, 3:1 panorama, 3:4 portrait and 9:16 tall.

Decisions

Decided questions are locked and show their API. For open ones, recommendations are preselected; click an option's letter in its section to change it.

1 · Grid display

The value in an index grid cell. Recommended candidate: 32px square thumbnail, cropped to fill, rounded corners. Empty shows a placeholder tile; a failed load shows a broken-image tile (hover for the reference). Click a thumbnail for the lightbox.

2 · Grid editor

The value edited inline, in a row in edit mode. The row's own Save and Cancel commit or discard every cell, so the image control has none of its own: it only stages the change, marked by an accent ring. Recommended candidate below, with Alfama in edit mode: click the thumbnail to pick a file or × to remove it, then the row's Save or Cancel.

3 · Display

The value on the view page and in row details. Recommended candidate: the picture in its own shape (no crop), capped at 15rem tall, with nothing under it. Click it for the lightbox (the grid display opens the same one).

For review: failed load and the lightbox (not decisions)

4 · Editor

The value on the create and edit forms. The user uploads a file; the app's storage handler saves it and returns the reference that goes in the property. The preview keeps the picture's own shape, like the display: an editor shouldn't crop what the user is about to save.

Recommended candidate

Choose a file, drag one in, replace, remove, undo. Uploads take ~1.5s (simulated); non-images and files over 5 MB are rejected.

For review: every state of the chosen layout (not decisions)
