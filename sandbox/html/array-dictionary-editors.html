Array and dictionary editors

One field with a row per value, for a list of primitive values (List<string>, int[], …) or for keyed values (Dictionary<string, T>, Dictionary<TEnum, T>). Every editor below is live: Enter adds a row, ↑/↓ move between rows, Backspace in an empty row removes it, pasting several lines (or key=value lines, or two spreadsheet columns) adds several, and Alt+↑/↓ moves a sortable row.

Row numbers and reordering

Two independent list options, both off by default. With both, the row's number turns into the grip while the row is hovered or focused. A dictionary can number its rows but not reorder them: its entries have no order to keep.

Edit form

Highlights is a sortable List<string> (1 to 8). Arrival airports is a unique string[] matching ^[A-Z]{3}$, upper-cased on entry. Departure days is an int[] from 1 to 31. Local names is a Dictionary<string, string> whose keys match ^[a-z]{2}$, with its own empty message. Seasonal prices is a Dictionary<Season, decimal>: the key is a select, a season can be used once, and Add stops when every season is in. Guides by language picks both its key and its value from supplied items. Baggage allowance is a Dictionary<string, int> in kg. Rows validate when they lose focus; Save validates everything and shows what would be posted.

Logistics

Configuration this form could come from (proposal, not final): 
fields.Add(t => t.Highlights).UseEditor<ListEditor>(list => list
    .Count(1, 8).Sortable().Placeholder("e.g. Tasting at a family-run tasca"));
fields.Add(t => t.ArrivalAirports).UseEditor<ListEditor>(list => list
    .Pattern("^[A-Z]{3}$", "Use a three-letter IATA code, like LIS.").Unique().UpperCase());
fields.Add(t => t.DepartureDays).UseEditor<ListEditor>(list => list.Range(1, 31).Unique());
fields.Add(t => t.LocalNames).UseEditor<DictionaryEditor>(dict => dict
    .Key("Language", key => key.Pattern("^[a-z]{2}$", "Use a two-letter language code, like pt."))
    .Value("Local name")
    .EmptyText("No translations yet. Pages use the English name."));
fields.Add(t => t.SeasonalPrices).UseEditor<DictionaryEditor>(dict => dict
    .Key("Season").Value("Price", value => value.Prefix("€")));   // enum key: a select, each season once
fields.Add(t => t.GuidesByLanguage).UseEditor<DictionaryEditor>(dict => dict
    .Key("Language", key => key.UseItems(Languages))
    .Value("Guide", value => value.UseResource<Guide>()));   // the same item sources as SelectEditor
fields.Add(t => t.BaggageAllowance).UseEditor<DictionaryEditor>(dict => dict
    .Key("Cabin").Value("Allowance", value => value.Range(0, 50).Suffix("kg")));

Read-only beside other fields

Each field as the panel renders it when IsReadOnly is set: text inputs, input groups and text areas are readonly and look editable; a select and a checkbox have no read-only state, so they are disabled; a multi-select lookup shows its items on the muted fill, and "None" in an input when it has none. Lists and dictionaries take the disabled select's fill for now.

Every editor, every state

Live editors in fixed starting states. "Invalid" shows errors as they would come back from Save: an item's error under its row (ModelState key Highlights[1], LocalNames[1].Key), a collection's error under the field (key Highlights).
