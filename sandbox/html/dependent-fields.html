Dependent fields

A field whose items depend on another field's value: a trip's city, airport and guides depend on its country, and its neighbourhoods and pickup points depend on its city. Changing a parent asks the server to re-render the dependent fields (simulated here), which clears values the new items don't contain. While a parent is empty its dependents are disabled. Every editor uses its existing markup and disabled styles; the open questions are about the hints around them.

Create form

Country is a select. City (select), overnight stop (lookup, input layout), arrival airport (lookup, card layout) and guides (multi-lookup, chips) depend on it; neighbourhoods (toggle group) and pickup points (checkbox group) depend on the city, so changing the country clears and disables them too.

Route

Configuration this form would come from (proposal, not final): 
fields.Add(t => t.Country).UseEditor<SelectEditor>(UseCountries);
fields.Add(t => t.City)
    .DependsOn(t => t.Country)
    .UseEditor<SelectEditor>(select => select.UseItems<CityChoices>());   // CityChoices reads form.Country
fields.Add(t => t.ArrivalAirport).UseEditor<LookupSheetEditor>(lookup =>
    lookup.UseItems<Db, Airport, string>(a => a.Code, a => a.Name, items => items
        .Where((Airport airport, Trip form) => airport.CountryCode == form.Country)));   // dependency inferred
fields.Add(t => t.Neighbourhoods).DependsOn(t => t.City).UseEditor<ToggleGroupEditor>(...);

Inline grid row

The same cascade in edit rows: country (select cell) → city (lookup cell) and guide (select cell). The refresh includes the row's own inputs (hx-include="closest tr", as Save does) and swaps the dependent cells. The second row is a new row, so its dependents start disabled.
