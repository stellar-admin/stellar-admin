Stacked sheets

Every lookup offers New, and every create form's lookups offer Choose and New again, so the stack has no limit. Each level is its own modal <dialog> created when it opens and removed when it closes, instead of the two fixed placeholders the layout renders today. Concepts A to F only change how the covered levels look; G avoids most levels by nesting create forms inline. Switch between them from the control bar while a stack is open.

Try it

  1. Lead guide → New guide, then Home city → New city, then Country → New country… Region's “Part of” is a region again, so it never ends.
  2. Or Choose a lookup, then New in its footer: creating selects the record in the field below and closes the lookup too.
  3. Esc, the close button and Cancel close only the top level. Back and the trail go down a level; a trail item or spine jumps several.
  4. In Push, Recede and Side by side, click a covered sheet to go back to it.

Shared by every concept

  • One modal dialog per level, so the browser keeps focus inside the top one, Esc closes only it and focus returns to the button that opened it.
  • The new record is selected in the field below; when it came from a lookup's New, the lookup closes with it.
  • A trail in each header names the path (Edit tour package › New guide › New city) with Back. Toggle it off to judge a concept without it.
  • Scrim: base darkens the page once and dims covered sheets; each gives every level its own scrim and blur, as the library does today.
  • Below 640px every concept is one full-width sheet with Back and the trail; Title bars keep their bars instead of the trail, and Inline still nests.

Concepts

Open questions

  • Jumping back several levels discards the forms above. Ask first when one of them has changes, or keep them as drafts?
  • Should the close button close only its level (as here) or the whole stack, with Esc for one level?
  • Push stops moving after three covered levels and Spines keep adding 40px per level; at nine deep, should older levels collapse into one “…” spine?
  • Should a covered level stay live (its sheet keeps its search and scroll position) — needed for Push and Recede, which show it?

What this means for the library

  • The layout's two fixed placeholders (dashboard-sheet, dashboard-nested-sheet) become a sheet created per level from a template, and the lookup and create views stop hardcoding which one they target: a field's opener targets “a new level above mine”.
  • sel-dialog sets body.style.overflow from its own dialog only, so closing a level clears it while the levels below are still open. With a stack it has to count open modal sheets. The prototype restores the lock after each close; without that the page scrollbar comes back over the sheets.
  • Esc has to be handled by the stack: Chrome groups modal dialogs opened without a user gesture and closes the whole group on one Esc. Clicks keep each level separate, but a sheet opened after a slow server response, or by script, can join the group.
  • Every sheet's backdrop blurs (backdrop-blur-xs), so with a scrim per level each covered level is blurred once more; the base scrim avoids that.
  • Covered levels move with the individual translate and scale properties, so they don't fight the sheet's enter animation on transform.
