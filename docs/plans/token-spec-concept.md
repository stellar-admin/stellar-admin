# Token spec concept

Status: concept, phase 7 of an experiment. Branch `token-spec-concept`. Nothing in the library has changed.

## Question

Can a StellarAdmin theme be a set of token values, read by theme-independent component CSS, instead of a full per-component stylesheet (about 1,200 lines for each generated shadcn theme and about 3,300 for each hand-authored one)? The test: express very different existing themes through tokens alone, and compare them against the current bundles. Phase 1 covered button, input, card, table and chip with Nova, Lyra, Maia and Aurora; phase 2 added dropdown menu, tabs, dialog and sidebar; phase 3 added the Concourse and Ledger themes; phase 4 added a knob layer, so a theme can break away from the existing themes entirely; phase 5 dropped shadcn compatibility, so knobs are the only theming route; phase 6 stress-tested the vocabulary with switch, badge and toast; phase 7 reworked the knobs around design decisions and contrast instead of reproducing the shipped themes.

## Prototype

`sandbox/html/token-spec/` holds the concept. Open `index.html` over the static server (`python3 -m http.server 8321` from the repository root). It shows each preset in light and dark, using the markup the tag helpers emit, and for the presets that reproduce a shipped theme (Nova, Concourse, Ledger) the current bundle beside it.

- `tokens.css`: tiers 0 and 1. The knobs, and the formulas that derive the foundation tokens (colour roles, type, role-based radii, control sizes, spacing, focus, elevation, motion) from them.
- `components.css`: tier 2 component tokens, declared on each component's selector and defaulting to tier 1, plus the component rules. These are plain CSS and never name a value.
- `presets/*.css`: themes as knob values.

Phases 1 to 3 had a second route, since removed (see phase 5): tier 1 defaults read from the shadcn palette names, `palettes/*.css` and hand-written `themes/*.css` (Nova 7 lines, Lyra 45, Maia 94, Aurora 301, Concourse 210 and Ledger 185, plus about 90 lines of palette each, against hand-authored bundles of 3,432, 2,522 and 2,268 lines). At the end of phase 3 there were 95 tier 1 tokens and 258 tier 2 tokens. Menus and dialogs are shown open in place; the sidebar is the default variant, expanded, at desktop width.

## Knob layer (phase 4)

The themes above reproduce existing designs. The knob layer tests the other direction: a base theme that a developer can turn into something StellarAdmin does not ship by setting a few values.

- `knobs.css` loaded after `tokens.css`, instead of a palette (merged into `tokens.css` in phase 5). About 20 knobs generate every tier 1 token: accent, danger, neutral hue and tint, accent tint in washes, surface depth, sidebar tint, line strength, radius, stroke, container edge (ring or border), elevation, density, type scale and focus width and offset. Fonts, weights and the section label case are tier 1 tokens that need no formula, so they act as knobs as they are.
- Required knobs have defaults on `:root`. Optional knobs (`--sa-accent-dark`, `--sa-danger-dark`, `--sa-radius-outer`, `--sa-on-accent`, `--sa-focus-color`) have no default and are read through a `var()` fallback, so when unset they re-derive in every scope.
- Colour comes from fixed OKLCH lightness steps per mode, tinted by the neutral hue and chroma. Text on the accent picks near-white or near-black from the accent's lightness, using relative colour syntax. One elevation value scales every shadow's opacity, about 2.5 times in dark mode.
- Density multiplies `--sa-unit` (0.25rem). The 24 tier 2 spacing tokens that were literals are now multiples of `--sa-unit`. The unit is 0.25rem without knobs, so the six token themes are unchanged. `data-density="compact"` and `"comfortable"` set the density for a section.
- Scoping: geometry formulas are declared on `:root`, `[data-density]` and `[data-sa-scope]`; colour formulas on `:root` and `[data-sa-scope]`, and again for `.dark` and `.dark [data-sa-scope]`. `[data-sa-scope]` marks any element that sets its own knobs.
- Structural switches are tier 1 tokens set to 0 or 1, which the tier 2 tokens read, so a theme can set them from `:root`. `--sa-footer-fill` and `--sa-footer-rule` choose a card footer band, a rule only, a tint only, or flush (no band and no gap above). `--sa-col-head-label` gives column heads the section label role (size, weight, colour and tracking, blended by the switch), and `--sa-col-head-fill` puts them on a sunken band. Text case is a keyword and cannot be scaled by a number, so it has its own token, `--sa-col-head-case`, which is set to `var(--sa-label-transform)` alongside the label switch. Font family has the same problem and is still per theme. For that reason `--sa-label-tracking` is now a length (`0em`) instead of `normal`. The defaults reproduce the earlier values, so the six token themes are unchanged.
- Pagination is the tenth component (`.sa-pagination`, using the shipped markup: buttons, with the current page as an outline button). `--sa-current-fill` blends the current page from outline (0) through a soft tint (0.15) to solid accent (1). The pager tokens that blend with the button's outline tokens are declared on `.sa-pagination-link`, because those button tokens exist only on the button. The specimen shows a standalone pager and a data grid–style footer pager in the knobs engine only, since the comparison themes had no pager tokens.
- A resource index sample (`sample=index`) renders the Dashboard's index page (`_IndexPage` and `_IndexDataGrid`): page header with Create, scope tabs, search input group, a data grid with sort links and row actions, and the footer with rows per page, range and pager. For this the concept gained a page container and header, an input group (the field is drawn by the group, which shares the input tokens), the data grid chassis (a card with the table bled to its edges) and sort links that take on the column head's type. `--sa-col-head-font` joins the column head switches; like case, it is a keyword. The outline button and active tab now default to the surface colour instead of the canvas. Ledger, Concourse and Aurora had all overridden them that way, and with a tinted canvas they read as grey.
- `presets/` holds eight presets of 11–22 knobs each: an attempt at Nova (the reproduction test), Concourse and Ledger built from knobs alone (to show how far the knobs reach before relief switches exist), Workshop (an approximation of the current resource index screenshot) and four themes unlike any shipped one: Terminal, Soft, Editorial and Ops.
- The dialog footer reads the footer switches through optional knobs, `--sa-dialog-footer-fill` and `--sa-dialog-footer-rule`, which fall back to the card's. In the shipped themes the dialog footer matches the card's in ten of fifteen; Aurora, Meridian, Observatory and Parallax band only the dialog, and Lyra rules only the card. A flush dialog footer drops its top padding, as the card's does. The builder has a "Dialog footer" control that defaults to "Same as card".
- Button switches (tier 1, read by the button and field tokens), added to reproduce Concourse's and Ledger's raised buttons: `--sa-control-relief` (0 flat; above 0 a border 0.1 darker than the fill on primary and destructive and a line border on secondary; up to 0.5 a drop shadow; from 0.5 to 1 a dark bottom edge, a hover lift, a pressed inset shadow and recessed fields, weighted up in dark mode), `--sa-danger-fill` (soft to solid, with `--sa-color-on-danger` for the text), `--sa-secondary-fill` (bordered surface to neutral fill) and `--sa-link-decoration` (a keyword). The knob layer gains optional `--sa-neutral-hue-dark` and `--sa-neutral-chroma-dark`, for themes whose greys change tint in dark mode. The builder has a Buttons group, including `--sa-press-offset`. The Concourse preset uses relief 0.25 and Ledger 1. At their defaults the switches leave the token themes' buttons and fields visually unchanged; the computed values gain transparent shadow layers and change notation (oklab).
- `builder.html` is a theme builder, with a toggle between the component specimen and the resource index sample: controls for every knob, including the structural switches (one control can set several tokens), presets, light and dark mode, a randomise button, and the changed knobs as copyable CSS. The preview is the specimen frame.

## No shadcn compatibility (phase 5)

StellarAdmin's token system does not need to accept shadcn or tweakcn palettes, so the prototype has one route: knobs generate tier 1, tier 1 feeds tier 2.

- `knobs.css` is merged into `tokens.css`: knobs, then the tier 1 tokens that need no formula (fonts, weights, section labels, structural switches, motion), then the geometry and colour formulas. The colour defaults that read the shadcn names, and the `.dark` block that adjusted them, are gone.
- The block that mapped tier 1 back to the shadcn names (`--background`, `--primary`, `--sidebar-*`, …) is gone. The specimen's page chrome reads tier 1 tokens instead.
- `palettes/` and `themes/` are deleted. The Nova, Concourse and Ledger presets stand in for them, and the comparison page pairs those three with their bundles; the other presets show the token engine alone. The page always shows pagination now.
- `--sa-color-neutral`, `--sa-color-neutral-hover` and `--sa-color-on-neutral` existed only because shadcn has `--secondary`. The secondary button reads the sunken surface, a 6% ink mix for hover, and the ink.
- Kept: `--sa-color-surface-raised` (lighter than the surface in dark mode, so menus and dialogs lift), and hover, selected and highlight, which are already one accent-tinted wash at three strengths.
- Not added yet: status colours (success, warning, info) and a text-safe accent. They need a consumer (badge, alert, toast, link text) before their formulas can be checked.
- The library cost: the shipped components are Tailwind utilities over the shadcn names. Migration still needs a temporary mapping for components not yet converted, removed with the last one, and the port-shadcn-component workflow will translate classes to tokens instead of copying them.

## Stress test: switch, badge and toast (phase 6)

Three components with more per-part detail than the first ten, converted with the shipped markup (`sa-switch-wrapper` > `sa-switch` + `sa-switch-thumb`, `sa-badge` with its six variants, and the toast template as `sel-toaster` fills it). The toast's stacking, swipe and enter/exit rules are behaviour and stay in the shipped `components.css`; the specimen shows toasts in place.

- No tier 3 rules and no new structural switches. New tier 1 values: three status colour knobs (`--sa-success`, `--sa-warning`, `--sa-info`) and their `--sa-color-*` tokens, raised to a minimum lightness in dark mode as danger is. New tier 2 tokens: 25 for the badge, 14 for the switch, 19 for the toast.
- `--sa-edge-mode` now also means "small parts draw borders": at 1 badges get a line border (a darker accent on the default badge, 45% danger on the destructive one, as Concourse and Ledger have), and the switch track gets a line border and a 2px inset thumb. At 0 they are borderless, as in Nova.
- The badge radius is the control radius. At Nova's 10px that is already a pill on a 20px badge; Concourse and Ledger get 4px and 6px, and Terminal square badges.
- The switch is sized from the control height (track 0.575 × control height, 1.75 × as wide, small 0.8 ×), so density scales it. The track recesses at high relief (Ledger's inset shadow).
- Toast icons take the status colours by type. This is a change: the shipped toasts colour only the error icon.
- Tier 2 lines in presets, inside component blocks (the builder's preview loads the preset file for them; its export holds only the knobs): Concourse's outlined switch (transparent track, control border, grey thumb when off), Ledger's 600 badge weight and dark thumb in dark mode. The builder gains the three status colours.
- Remaining differences from the bundles: switches 2–5px narrower in Concourse and Ledger (they are larger than proportional), toast radius (container radius: Nova 14px against 18px, Concourse 6px against 4px, Ledger 9px against 6px), Concourse's outline badge (muted text, stronger border), and the known ramp differences (Nova's lighter off track, Ledger's paler secondary).
- Finding in the shipped library: in Nova dark, a checked switch keeps the unchecked track (`dark:bg-input/80` overrides `checked:bg-primary`), so on and off differ only in the thumb. The token version shows the accent track.

## Knobs as design decisions (phase 7)

Goal change: the knobs no longer try to reproduce the shipped themes. They should be a small set of clear decisions that look good across every component and every combination. Presets are showcases built from knobs alone; one that needs a tier 2 line points to a missing knob or a wrong default.

- `--sa-edge-mode` is gone. Containers (card, menu, dialog) always draw a `--sa-stroke` border; the outside ring added nothing a viewer could see.
- `--sa-outlines` (0 or 1): filled parts draw an outline too. At 1 the primary button and badge get a border a step darker than the fill, secondary buttons and badges and chips a line border, the destructive badge a 45% danger border, and the switch a bordered track with an inset, grey thumb. At 0 only outline-style parts have borders.
- `--sa-pills` (0 or 1) sets `--sa-radius-tag`, the radius of tags (badges, chips, the switch): pills, or the control radius. The switch thumb is concentric with its track, so a square theme gets a square switch.
- `--sa-relief` has three levels instead of a 0–1 blend: 0 flat, 1 raised (a drop shadow), 2 tactile (also a bottom edge, a hover lift, a pressed state, and recessed fields and switch tracks). Borders now come from `--sa-outlines`, not relief.
- Contrast is built in. Solid fills (primary buttons, default badges, the switch, the current page, bold menu highlights, the sidebar accent) read `--sa-color-accent-fill` and `--sa-color-danger-fill`, and the text on them `--sa-color-on-accent` and `--sa-color-on-danger`, all computed from WCAG luminance: CSS converts the colour to linear sRGB, clipped to the gamut, and sums the weighted channels. Text is white below luminance 0.18 and near-black above it. A fill between luminance 0.18 and 0.37 (roughly lightness 0.57 to 0.72, depending on hue) reaches 4.5:1 with neither, so it darkens, keeping its hue, to 0.175, where white passes; saturated oranges and reds also read better with white than the formula suggests. Focus rings, washes and tints keep the colour as set. A lightness cut-off failed: a cut-off at 0.7 put white text on mid-tone fills, one at 0.57 put near-black text on Workshop's and Ops' oranges, and a fixed 0.55 target still failed for greens and out-of-gamut colours. `--sa-color-accent-text` (link buttons and link badges) caps the accent at lightness 0.5 and chroma 0.2 in light mode and raises it to 0.75 in dark mode; `--sa-color-danger-text` (destructive badges, soft destructive buttons, destructive menu items, field errors) caps danger at 0.48 and raises it to 0.75. It replaces `--sa-color-on-danger-soft`.
- Presets: Concourse and Ledger are "in the spirit of" the shipped themes, from knobs alone (outlined, square tags, raised or tactile). Their tier 2 blocks and Ledger's `--sa-danger-dark` are gone. Terminal, Editorial, Ops and Workshop are outlined with square tags; Nova, Soft and the base theme keep pill tags.
- The builder has Tags, Outlines and Relief controls under "Shape and depth", randomises them, and no longer loads preset files into the preview.

Limits found:

- The knobs cannot reproduce Nova exactly. The geometry is within a few pixels (menu radius 12.5px versus 10px, card height 6px), but the colours are a lightness step off (ink 0.18 versus 0.145, the dark card 0.155 versus 0.205), because the ramps are the base theme's own. An exact match needs about five tier 1 overrides on top of the preset, or a contrast knob.
- Raised buttons first could not be built from the knobs (see the button switches above). Remaining differences in the Concourse and Ledger presets are small: Ledger's secondary fill is a less saturated tan, its dark destructive red is a little lighter than the theme's (0.7 instead of 0.65, set through `--sa-danger-dark`, because the automatic text colour turns dark only from lightness 0.7), and the knob layer's elevation adds a faint extra shadow layer under buttons.
- CSS cannot check contrast. Automatic text on the accent covers the main case; other combinations, such as a high accent tint with a low line strength, can still produce weak contrast.



- Three tiers: foundation tokens, component tokens, and a raw override layer as the escape hatch. No theme needed tier 3 for any of the nine components.
- Radii are by role (`control`, `container`, `overlay`, `item`, `inner`, `round`), not by scale. This is what lets Lyra (all square), Maia (pill controls) and Aurora (square, round only where it carries meaning) differ with three values.
- Scoping: derived tier 1 tokens are declared on `:root, .dark`, and tier 2 tokens on the component selector, never on `:root`. Otherwise a nested `.dark` scope (as `MenuColor.Inverted` uses) keeps the outer values. The nested-scope section of the prototype verifies this.
- Structural differences become tokens, not rules: for example the card footer fill, the header divider band, the table head font and case, link underline, and Aurora's solid destructive button.
- Modifiers never redefine tokens. A modifier class such as `sa-menu-accent-bold` picks between tier 2 tokens through a private `--_*` variable, as the button variants do. This keeps a theme from overriding the modifier, and it fixes a bug in the shipped shadcn themes (see Verification).
- Cross-component roles belong in tier 1: section labels (`--sa-label-*`, used by menu labels and sidebar group labels, and by Aurora's table heads), highlighted rows (`--sa-color-highlight`), raised surfaces (`--sa-color-surface-raised`), and the sidebar as its own navigation palette (`--sa-color-nav-*`).
- Line height travels with type size: `--sa-leading-ui` pairs with `--sa-text-body`, so Lyra's smaller type does not inherit taller rows.
- Focus and invalid rings are complete shadow values (`--sa-focus-shadow`, `--sa-focus-shadow-field`, `--sa-invalid-shadow`, `--sa-invalid-focus-shadow`), composed with the control's own shadow. A width and a colour could not express Concourse's offset ring or Ledger's invalid halo at rest.
- Buttons have a border, a pressed fill and a shadow for each variant and state. Ledger's tactile buttons change shadow on hover and press; Concourse keeps the variant's border on focus (`--sa-button-focus-border-mix: 0%`).
- Container edges are either an outside ring that takes no space (shadcn) or a border that does (the hand-authored themes), chosen with `--sa-edge-ring` and `--sa-edge-border`. The 2px difference is enough to rewrap text in a dialog.
- Shadow tokens default to `0 0 #0000`, never `none`, because they are composed into `box-shadow` lists.
- Layers: `sa.reset, sa.tokens, sa.components, sa.theme, sa.overrides`.
- Density is a scope (`data-density="compact"`), not a theme.

## Verification (2026-10-09)

Phase 1: I compared headless Chromium screenshots of all four themes against the current bundles: Nova light and dark, Aurora light and dark, Lyra light and Maia dark. They match closely; the remaining differences are a pixel or two of vertical rhythm.

Phase 2: a CDP script compared the size, font size, radius and colours of 23 representative elements in both engines, for every theme in light and dark mode. After fixes, the remaining differences are at most 7px of card height (form label leading), a 2px menu width in Aurora, and Maia's 12px versus 14px radius on sidebar labels and sub-items (Maia redefines `--radius` inside the sidebar). Screenshots of the new sections were reviewed for Nova light, Aurora light, Maia dark and Lyra light.

Phase 3: the same script for Concourse and Ledger in light and dark, and the four earlier themes again in dark after the spec changes. Every element is within 2px (button widths, card heights) apart from invisible radii on unfilled elements; Aurora's dialog and menu are 3px taller. Screenshots reviewed for Concourse light and Ledger light and dark.

Finding in the shipped library: in the shadcn themes and Ledger, a menu that is both inverted (`MenuColor.Inverted`) and uses the bold accent (`MenuAccent.Bold`) shows the ordinary accent highlight. The `.dark` palette rule redeclares `--accent` on the same element, cancelling the bold override. Bold alone works; Aurora and Concourse are not affected. The token version renders it correctly.

Phase 4: screenshots of the base theme in light and dark (all sections), the Terminal, Soft and Editorial presets in light and Ops in dark, and three random themes from the builder. All read as deliberate designs; none broke the layout. The text on the accent resolved to near-black for a light dark-mode accent, confirmed through its computed colour. A CDP script drove the builder: the soft preset gave 37px pill buttons, density 0.75 reduced them to 24px, randomise produced a theme, and the knobs survived a switch to dark mode. The Nova preset was measured against the Nova bundle in light and dark (results under Knob layer). The computed `--sa-unit` is 0.25rem in all six token themes.

Phase 4, switches and pager: the measurement script against the bundles for all six token themes in light shows the same card, table head, cell and dialog footer results as before the switches. Screenshots of the pager section in the base theme, Terminal (label heads on a band, rule-only footer, solid current page) and Soft in dark (flush footer, soft current page). A CDP script set the builder's column heads to "Label on band", the footer to "Flush" and the current page to solid. It confirmed the 12px label heads, the sunken header band, 0px footer padding with transparent rule and fill, the accent current page with near-white text, and the exported CSS. Loading the Terminal preset selected the matching options.

Phase 4, resource index sample: screenshots of the sample at 1400px with Workshop (close to the reference screenshot of the current page), Soft in dark and Terminal. The measurement script still matches the bundles for the outline button and tabs in Nova (light and dark), Lyra and Maia (light and dark) after the surface default. A CDP script switched the builder to the resource index view, loaded Workshop (monospaced heads) and switched the head font back to the body font.

Phase 4, dialog footer switches and raised buttons: the computed card and dialog footers (fill, rule, padding, bleed) for the Nova, Lyra, Concourse and Aurora token themes are as before. The base knobs and Workshop follow the card footer, and Soft is flush with no top padding. Setting `--sa-dialog-footer-fill: 1` on Workshop gave the dialog a band while the card stayed rule-only. Screenshots compared the Concourse and Ledger bundle buttons with knob-only approximations (accent, neutral hue, radius, border edge, elevation, font). Screenshots of the Concourse and Ledger knob presets in light, next to their bundles, and of Ledger's resource index in dark.

Phase 4, button switches: the measurement script for all six token themes in light gives the same results as in phase 3. The computed button and field styles for Nova and Aurora (token engine against bundle) differ only by transparent shadow layers and colour notation. With forced :hover and :active, the Ledger preset's primary button matches the bundle's shadows, 1px press and border exactly, apart from the elevation layer; Concourse's showed a 0.1 drop shadow against the bundle's 0.05, so its preset moved from relief 0.5 to 0.25. Screenshots of both presets against their bundles in light and dark. A CDP script loaded the Ledger preset in the builder and confirmed the relief, destructive, dark neutral hue and link controls and a solid destructive button in the preview.

Phase 5, restructure: a CDP script captured 18 computed properties (colours, borders, shadows, radius, padding, type, size) of every element in the specimen and the resource index sample, for the base theme and all eight presets in light and dark (36 pages, 10,710 elements), before and after the restructure. There are no differences. The secondary button's forced hover matches the old neutral hover mix in light and dark. The comparison page shows the Ledger bundle and preset side by side, Editorial alone with the view switch hidden, and the builder preview loads.

Phase 6, stress test: a CDP script measured size, colours, border, radius, shadow and type of every badge, switch track and thumb, toast part and toast icon for Nova, Concourse and Ledger in light and dark, against the bundles; the remaining differences are those listed under phase 6. The phase 5 snapshot, excluding the three new sections, still matches for all presets and modes; only the specimen's height changed. Screenshots of the new sections for Concourse light and Ledger and Nova dark (each beside its bundle), Soft light and Terminal dark. A CDP script loaded Ledger, Editorial and the base theme in the builder and randomised: the preview picked up Ledger's tier 2 badge weight and `--sa-danger-dark`, Editorial's heading font, and the base export was empty.

Phase 7, contrast and random themes: a CDP script (`contrast.mjs` in the session scratchpad) loads every preset and a set of seeded random themes (every third at extreme values: accent lightness 0.3 or 0.88, chroma up to 0.3, neutral tint 0.04, line strength 0.4 or 2, elevation 3, density 0.7 or 1.4), in light and dark, for the specimen and the resource index sample. For every visible element with its own text it composites the background layers and checks WCAG contrast (4.5:1, or 3:1 for large text; disabled and hidden elements are skipped). Before the contrast changes 12 random themes and Ops, Workshop, Terminal and the dark Concourse and Ledger presets failed, all on white text over mid-tone fills and on link text; after them 0 of 20,592 text elements fail across 132 pages (seed 11, 24 random themes), and 0 for the first batch (seed 7, 12 random themes). Screenshots of Concourse light, Ledger dark, Terminal light and an extreme random theme in light and dark; the outlined switch's white thumb was hard to see, so outlined switches now have a grey thumb when off. After the luminance-based fills (prompted by near-black text on Workshop's and Ops' orange buttons): four seeds (7, 11, 23, 41; 84 random themes, a third extreme) give 0 failures in 74,880 text checks over 480 pages. The run found two faults on the way: out-of-gamut colours (fixed by clipping the channels before summing) and a soft step that turned white text grey when a fill sat within 0.001 of the threshold (the steps are now sharp). The checker also disables transitions, which had caught buttons mid-fade. Screenshots of the Workshop, Ops and Terminal buttons: white text on a slightly deeper fill; Ops' safety orange becomes a burnt orange on fills.

Not covered: hover, focus, active and invalid-focus states (apart from forced `data-open` and `data-active`); mobile widths; the collapsed, floating and inset sidebar variants; vertical tabs; and the dialog backdrop.

## Open questions

- Should Tailwind stay in the component layer? The concept needs none.
- Naming: should the tier 1 token names be public API at the first release?
- Migration path: convert one component at a time behind the existing class names, with a temporary internal mapping from tokens to the shadcn names for components not yet converted.
- Tier 2 is large (237 tokens). Before it becomes public API, it needs a naming grammar (`--sa-<component>-<part>-<property>-<state>`) and a decision on which tokens are public and which are internal.
- Next test: the interaction states and sidebar variants not yet covered, and the remaining themes (Ice, Meridian, Observatory, Parallax and the other shadcn styles).
