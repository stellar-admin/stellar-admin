# Meridian

Meridian is a warm, print-inspired operations theme: paper and deep umber surfaces, brass accents, 2px corners, and a deliberate split between Instrument Sans display headings, Work Sans UI text and JetBrains Mono data. Jerrie supplied the Claude Design handoff and authorized autonomous end-to-end implementation on 2026-09-12, explicitly selecting trailing menu checkmarks.

## Authority and maintained sources

The maintained implementation is [meridian.css](../../../src/StellarAdmin.TagHelpers/Client/css/themes/meridian.css). Its foundation tokens preserve the exact handoff values. Jerrie accepted the completed theme on 2026-09-12, including the final removal of the horizontal line-tab list border. This specification and CSS govern future extensions and supersede the original handoff. Its runnable HTML/CSS informed implementation; its downscaled screenshots and inconsistent prose were secondary references. The temporary handoff is not required for future work. The selector mapping uses existing StellarAdmin component contracts; Meridian imports no other theme and is not generated by ThemeGenerator.

Consumers link `stellar-admin.meridian.css` and use the usual `.dark` class. Optionally load Instrument Sans (normal 600), Work Sans (normal 400/500/600), and JetBrains Mono (normal 400/500) from the application layout. The library CSS does not fetch fonts. The handoff identifies all three families as SIL OFL 1.1; no binaries were supplied. Font loading URL: `https://fonts.googleapis.com/css2?family=Instrument+Sans:wght@600&family=Work+Sans:wght@400;500;600&family=JetBrains+Mono:wght@400;500&display=swap`.

## Optional fonts and native fallbacks

Decision accepted on 2026-09-14 after reviewing both showcase pages in light and dark mode: retain the original font families for their character, with the approved native stacks as fallbacks. Font loading is optional for consumers. Linking only the theme bundle requires no font downloads; an application can add the Google Fonts stylesheet above (or self-host the fonts) to restore the original typography. The sample apps and exported website demos load only the selected theme's font families with `display=swap`, showing native text while fonts load and switching when ready. A late swap can change text widths and wrapping; applications that prefer to avoid a late swap can choose `display=optional`, which may keep the native font for that page view.

The maintained CSS uses the following family order:

```css
font-family: "Work Sans", "Helvetica Neue", Helvetica, Arial, "Liberation Sans", system-ui, sans-serif;
/* Data, identifiers and shortcuts */
font-family: "JetBrains Mono", ui-monospace, "SFMono-Regular", Menlo, Consolas, "Liberation Mono", "DejaVu Sans Mono", monospace;
```

Display headings prefer `"Instrument Sans", "Work Sans"` before the same native sans stack; keep their existing weight and tracking.

Preserve the existing sizes, weights, tracking and line heights. Native font selection varies by operating system and installed fonts; the accepted screenshots cover Linux Chromium, not Windows or macOS. Future visual checks should exercise both loaded web fonts and native fallbacks, including small labels, dense controls and text wrapping. The bundle must not add remote font imports or require JavaScript for fallback.

## Foundations

Exact values live in the opening `--sa-meridian-*` foundation sections, mapped to StellarAdmin's public semantic palette and font variables in root and dark scopes. Preserve warm neutrals, deep brass in light mode and lit brass in dark mode. Cards lose their shadow in dark mode; inputs and overlays use the brighter umber surface. Default controls are 32px, small 26px, large 40px, and inferred extra-small 22px. Table cells use the handoff's default 11px vertical padding; override the private row-padding token for a compact application without adding a preference API.

Body/control text is 13px. Instrument Sans 600 is reserved for display headings (14px cards/alerts/empty states, 15px dialogs/sheets, 17px page titles). Work Sans handles labels, actions and body text. JetBrains Mono handles table micro-headings, shortcuts and explicitly marked data. Applications use `font-mono tabular-nums` for identifiers/numbers; CSS cannot identify numeric substrings in arbitrary text. Radii are 2px without a nesting scale, 1px for progress, and pills for badges/avatars/switches. Motion uses 120/180ms timings where existing component contracts permit; reduced motion suppresses library animation.

## State rules

Neutral hover and pressed surfaces signal transient feedback. Selection uses a checkmark, filled control, raised tab thumb, underline or brass tint depending on the component. Both dropdown checkbox and radio items reserve a trailing 16px checkmark slot, with no resting selected row fill. Reuse the emitted SVG; unchecked indicators remain hidden. Hover is neutral; keyboard focus adds a 2px inset brass rail. Standalone radios retain their circular dot. Explicit menu color/appearance variants retain their public meanings.

Selected table rows keep their brass tint while hovered. Default tabs and segmented controls share a sunken track, 3px padding, 2px inner corners and a raised selected surface. Line tabs use brass text and a 2px underline, following the source CSS rather than its 3px prose. Focus stays visible during pressed/checked states; focused invalid fields use the danger halo, with validation also working through model-bound classes.

## Composition recipes

Fields own vertical rhythm; the standalone control owns its edge and focus. Input groups own their outer edge, fill and focus ring; inner fields are transparent and borderless, addons own internal separators. Preserve block addons, textareas and nested groups. Cards own their surface, border and shadow; headers use 12px/16px insets, body 16px, footers a separating rule. Small cards use 12px body insets. Tables retain their existing wrapper and horizontal scrolling.

Menus and overlays own border and elevation; existing positioning, keyboard navigation, viewport containment and dismissal remain intact. Dialogs use a 440px default maximum, small alert-dialog semantics, 16px insets and tinted footers. Sheets retain their declared side and pinned footer. Sidebars preserve floating/inset and collapse contracts; navigation stays scrollable. Empty states are borderless by default but retain semantic border color when a consumer adds a border utility.

## Inferences and limits

- Preserve library sidebar breakpoints, sheet sides and scrollable tables. The prototype's automatic bottom sheet and table-to-card conversion are application choices requiring behavior changes beyond theme CSS.
- Use matching 3px gaps for default tabs and segmented controls; the source inconsistently uses 2px for enclosed tabs and 3px for segmented controls despite describing identical geometry.
- Ship the source's default table rhythm, without a new density preference or configuration API.
- Infer missing families from their nearest primitives: OTP from fields/mono text; attachments, bubbles and messages from cards/badges; questionnaire/form sections from fields and selection; calendar-like future controls from accent endpoints and tinted ranges. Do not invent new component APIs.
- Preserve the palette rather than assuming the handoff's contrast claims are correct. Measured light control borders are about 1.78:1 against the card surface, subtle text 4.38:1 on the page, and warning text 3.87:1 on its tint. These fall below the handoff’s stated 3:1/4.5:1 targets. The selected palette is preserved for visual review; no accessibility certification is implied.
- **Dark input correction:** the handoff’s late `:root` alias overwrites its explicit dark input token. Restrict the alias to light mode so dark inputs use the intended raised `#23201a` surface.
- Keep native selects at the source's 13px. Observatory's platform-specific 12.5px workaround is not evidence that Meridian needs it.
- Use existing Lucide icons and runtime behavior. The export's topology illustration, icon sprite, simulated states and scripts remain reference assets.

Horizontal line tab lists have no full-width bottom border; only the active tab draws its accent underline. This review preference applies to standalone tabs and page-header navigation.

## Adding controls

Start from the real component contract and choose the closest maintained recipe. These mappings guide future designs; they do not claim those controls already exist:

| New control or part | Meridian starting point |
| --- | --- |
| Searchable or multi-value picker | Input-group outer border and focus, menu panel, trailing checked indicators, secondary badges for values. |
| Calendar or date range | Compact actions with 2px corners, brass endpoints, soft accent range fill, existing field validation. |
| Tree or step navigation | Sidebar rows and disclosure icons; use current-step accent text and keep hover distinct from selection. |
| Upload area or editor | Field/group ownership of border and focus, card surface, attachment rows and existing status colours. |
| New overlay | Menu or dialog elevation, Instrument Sans title, Work Sans body, constrained scrollable content and reachable footer. |
| Data display | Table spacing, mono labels/explicit values and semantic status badges; do not make all body text monospace. |

Inspect the Tag Helper, shared CSS and web component before mapping selectors. Implement every supported size, variant, orientation and state, including disabled, invalid, selected hover and keyboard focus. Keep behavior in the existing component contract. Add a real sample and coverage evidence; compare related primitives in light/dark at desktop/mobile widths. If a shared hook is needed, preserve its fallback and verify other themes. Follow the [custom-theme workflow](../custom-theme-workflow.md) and the component-porting workflow when adding an upstream control.
